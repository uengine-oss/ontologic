# 에이전트 백엔드와 LLM 접속 — 두 경로를 갈라 놓는다

**결정일** 2026-08-02 · **결정 주체** 사업 판단 ·
**상태** 결정됨 — **첫 실행 선택 화면 구현 완료(2026-08-03)**, text2sql·인제스천 리팩토링은 미착수

> **구현 현황은 이 문서 맨 아래 §"구현된 것과 남은 것" 에 있다.** 아래 본문은 결정 당시의
> 판단 그대로 두었다 — 결정과 구현 결과를 같은 자리에서 고쳐 쓰면, 나중에 "왜 그렇게 정했나"
> 를 되짚을 근거가 사라진다.

이 문서는 데스크톱 실행 중에 드러난 문제와 그 해법을 기록한다. 실행해 보기 전에는
보이지 않던 문제다.

## 무엇이 문제였는가

첫 기동에서 text2sql 컨테이너가 **기동 자체를 거부했다.**

```
RuntimeError: OPENAI_API_KEY is missing but embedding_provider=openai
[CRITICAL][startup.sanity] startup.sanity.failed {'failed': ['openai']}
```

`AGENT_BACKEND=cliagents` 로 Claude Code 를 쓰면 OpenAI 키가 필요 없다는 것이
데스크톱 패키징의 전제였다([desktop-packaging-decisions.md](desktop-packaging-decisions.md) §1).
그런데 **text2sql 은 에이전트 백엔드와 무관하게 자기 몫의 LLM·임베딩을 직접 부른다.**
전제가 절반만 맞았던 것이다.

결과: 키를 넣지 않은 첫 사용자는 **앱 화면 자체를 못 본다.** "다운로드 한 번으로 로컬에서
돈다"는 가치 제안 1번이 첫 실행에서 깨진다.

## 결정 — LLM 접속은 백엔드 선택에 종속된다

| 경로 | 사용자가 입력할 것 | 근거 |
|---|---|---|
| **`deepagents`** (인프로세스 LangChain) | **LLM 접속 정보** — 엔드포인트 · 모델명 · 키(필요한 경우) | 우리가 LLM 을 직접 부르므로 어디로 부를지 알아야 한다 |
| **`cliagents`** (Claude Code · Codex) | **아무것도** | CLI 가 자기 모델과 로그인 세션을 들고 온다 |

### `deepagents` 는 "OpenAI 키"가 아니라 "접속 정보"를 받는다

지금 설정 파일은 `OPENAI_API_KEY` 를 받는 형태다. 이것은 **로컬 LLM 을 배제한다.**
데스크톱 제품의 핵심 주장이 "데이터가 이 PC 를 떠나지 않는다"인데, LLM 만 클라우드로
나가면 그 주장이 반쪽이 된다. 로컬 LLM(Ollama, vLLM, LM Studio 등)을 쓰려는 사용자가
정확히 우리의 표적 고객이다.

받아야 하는 것:

- **엔드포인트 URL** (OpenAI 호환 base URL — 로컬이면 `http://localhost:11434/v1` 류)
- **모델명** (major / minor 구분 유지)
- **API 키** — 로컬 LLM 에서는 **비워 둘 수 있어야 한다**

즉 키를 필수 항목으로 두면 안 된다. 필수인 것은 **엔드포인트**다.

### `cliagents` 에서는 text2sql·ingestion 을 스킬로 돌린다

**이것이 이 문서의 핵심 결정이다.**

현재 text2sql 과 문서 인제스천은 자기 LLM 을 직접 부르는 **별도 서비스**다. 그래서
`cliagents` 를 쓰는 사용자도 LLM 접속 정보를 따로 넣어야 하고, 안 넣으면 스택이
완성되지 않는다. 두 개의 LLM 설정이 한 제품 안에 공존하는 구조다.

이를 **스킬 기반 실행으로 리팩토링한다.** `cliagents` 경로에서는 text2sql 과 인제스천을
CLI 에이전트가 스킬로 수행한다. 그러면:

- 사용자는 **LLM 설정을 한 번도 하지 않는다.** CLI 가 이미 인증돼 있다.
- LLM 호출 지점이 **하나로 모인다.** 지금은 백엔드·text2sql·인제스천이 각자 부른다.
- 플랫폼 계약과도 맞는다 — *"스킬은 배포 가능한 표준 패키지다"*, *"지시문은
  `skills/<name>/SKILL.md` 하나가 원천"* (constitution). text2sql 프롬프트가 지금
  파이썬 안에 있다면 그 계약을 이미 어기고 있는 것이다. (확인 필요)

이는 **spec 004(교체 가능한 에이전트 백엔드)의 자연스러운 연장**이다. 004 가 "누가
에이전트를 실행하는가"를 교체 가능하게 만들었다면, 이 결정은 그 교체 범위를
text2sql·인제스천까지 넓힌다.

## 이 결정이 바꾸는 것

| 대상 | 지금 | 결정 이후 |
|---|---|---|
| 설정 파일 | `OPENAI_API_KEY` 필수처럼 보임 | `deepagents` 일 때만 접속 정보 요구. `cliagents` 면 비워 둠 |
| text2sql 컨테이너 | core 팩, 키 없으면 크래시 | `cliagents` 경로에서는 **불필요해질 수 있다** — 팩 경계 재검토 대상 |
| 첫 실행 경험 | 키 없으면 앱이 안 뜸 | 키 없이 완전 동작 (CLI 만 설치돼 있으면) |
| 메모리 | text2sql 컨테이너 상주 | 컨테이너가 빠지면 실측 재측정 필요 |

마지막 줄이 중요하다. [memory-footprint-measurement.md](memory-footprint-measurement.md)
가 잰 text2sql 호스트 프로세스 214.8 MiB 는 이 리팩토링 이후 **사라질 수 있다.**
8GB 스펙 판단(권장 16GB / 최소 8GB)을 그때 다시 본다.

## 임시 조치 (이미 적용)

리팩토링 전까지 첫 실행이 죽지 않도록, text2sql 실패를 **비치명으로 강등**했다.
앱은 뜨고 "데이터소스 자연어 질의 비활성 — 온톨로지 설계와 그래프 조회는 사용 가능"
이라고 알린다. (`desktop/src/main/index.js`)

이것은 해법이 아니라 **다리**다. 위 리팩토링이 끝나면 이 분기의 의미가 바뀐다.

## 아직 확인하지 않은 것

- text2sql 의 프롬프트가 어디에 있는가 — 파이썬 안이면 계약 위반이고, 스킬로 옮기는
  작업의 첫 단계가 된다
- 인제스천(문서 파싱·임베딩)의 LLM 호출 지점과 임베딩 의존성. **임베딩은 CLI 에이전트가
  대신해 줄 수 없다** — 벡터를 만들어야 하므로 임베딩 모델 접근이 별도로 필요하다.
  이 부분은 스킬로 옮겨도 남는다. 어떻게 처리할지가 이 리팩토링의 가장 어려운 지점이다.
- `deepagents` 설정 UI 를 부팅 화면에 넣을지, 앱 안 설정 화면에 넣을지

# 구현된 것과 남은 것

**2026-08-03 갱신.** 아래는 결정이 아니라 **실행해서 확인한 결과**다. 화면으로 본 것과
코드만 있는 것을 구분해 적었다.

## 구현됨 — 첫 실행 에이전트 선택 화면

위 표의 "사용자가 입력할 것" 을 **첫 실행 화면 하나**로 옮겼다. 설정 파일을 손으로 여는
일이 더는 필요 없다.

| 항목 | 어디에 | 확인 방법 |
|---|---|---|
| 선택 화면(3지선다) | `desktop/src/renderer/boot.html` 의 `#agent-select` | 화면 확인 — evidence `01-agent-select.png` |
| 설치 여부 탐지 | `desktop/src/main/studio.js` `detectAgentClis()` — `resolveAgentBackend` 과 **같은 `which`** | 화면에 실제 경로가 표시된다 (`/opt/homebrew/bin/claude`) |
| 선택 결과 기록 | `<userData>/ontology-studio.env` 줄 단위 갱신 (`settings.updateEnv`) | 주석이 보존된 채 `AGENT_BACKEND` 만 바뀐다 |
| 다시 묻지 않음 | `stack.json` 의 `agentConfigured` | 두 번째 기동에서 화면이 뜨지 않는다 |
| 다시 고르기 | 메뉴 「런타임 → 에이전트 백엔드 변경…」 | 코드만 — 아래 "확인하지 못한 것" 참조 |

### 왜 부팅 화면 안인가

`AGENT_BACKEND` 는 백엔드 **프로세스 환경**으로 주입되므로 `studio.start()` 전에 정해져야
한다. SPA 는 그 백엔드가 서빙하는 화면이므로, 선택을 SPA 안에 두면 **반드시 한 번은 틀린
백엔드로 뜬 다음 재기동**하게 된다. 게다가 `cliagents` 인데 CLI 가 없으면 `warm_up_agent()`
가 예외를 던져 백엔드 자체가 뜨지 않아 SPA 가 아예 없다.

또 컨테이너 기동(첫 실행 수 분)보다 **먼저** 묻는다. 순서를 뒤집으면 사용자는 수 분을
기다린 뒤에야 질문을 받는다.

### "키가 아니라 엔드포인트" 를 코드로 옮긴 지점

`studio.js` 의 `resolveAgentBackend` 는 `deepagents` 에서 `OPENAI_API_KEY` 만 보고 경고했다.
이제 **엔드포인트 또는 키 중 하나**만 있으면 정상으로 본다. 화면의 필수 표시도 엔드포인트에
붙어 있고, 키 입력란에는 "로컬 LLM 이면 비워 두세요" 라고 적혀 있다.

부수적으로 `OCR_MODEL` 도 함께 맞춘다. 기본값이 OpenAI 공식 모델 이름이라, 사용자가 자기
엔드포인트를 넣는 순간 **존재하지 않는 모델**을 가리키게 되기 때문이다.

## 확인하지 못한 것 / 남은 것

- **`deepagents` 를 실제로 골라 돌려 보지 못했다.** 이 개발 머신에는 도달 가능한 OpenAI 호환
  엔드포인트가 없다. 화면과 설정 파일 기록까지는 확인했고, 그 뒤 `deepagents` 가 그 접속
  정보로 실제 응답을 내는지는 **확인하지 못했다.**
- **메뉴 「에이전트 백엔드 변경…」 을 화면으로 눌러 보지 못했다.** 이 세션의 셸에서
  macOS 메뉴바를 조작할 방법이 없다. 코드 경로는 `reconfigureAgent()` 이고, 컨테이너를
  건드리지 않고 호스트 프로세스 둘만 다시 띄운다.
- **text2sql 은 여전히 자기 몫의 LLM·임베딩을 직접 부른다.** 이 문서의 핵심 결정(§"`cliagents`
  에서는 text2sql·ingestion 을 스킬로 돌린다")은 **미착수**다. 실제로 이번 실행에서도
  text2sql 컨테이너는 키가 없어 기동에 실패했고, 임시 조치(비치명 강등)가 그대로 동작해
  앱은 떴다. 즉 첫 실행 경험은 "선택 화면 → 앱 진입" 까지 깨지지 않지만, **데이터소스
  자연어 질의는 여전히 비활성**이다.
- 위 세 번째 항목 때문에, 표의 "`cliagents` → 사용자가 입력할 것: 아무것도" 는 **에이전트
  대화에 한해서만** 참이다. 스택 전체로 보면 아직 절반이다.

## 곁가지로 확인된 것 — 스킬은 코드 변경 없이 늘어난다

같은 작업에서 브리프 초안 기능(`skills/ontology-brief-draft`)을 추가했는데, 스킬 목록·배포
메타데이터·MCP 엔드포인트가 전부 **폴더 스캔과 모드 상수 한 줄**로 따라왔다. constitution 의
"스킬은 배포 가능한 표준 패키지다" 가 실제로 그렇게 동작한다는 첫 사례다.
